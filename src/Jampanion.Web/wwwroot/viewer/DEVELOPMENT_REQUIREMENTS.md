# Jazz Chart Viewer — 開発要件・Validation セット

この文書は、今後の修正で守るべき要件と、修正後に行う検証をまとめた開発用の基準です。
表示の細部を変更する場合も、譜面の展開順と記号の意味を最優先します。

## 1. 基本情報

- 対象アプリ: Jazz Chart Viewer（静的ブラウザアプリ）
- 対象ブランチ: `main`
- 現行バージョンの目安: `v0.1.82`
- 配布先: <https://over-keys.github.io/Jazz-Chart-Viewer/>
- 実装: `index.html` に自己完結したHTML/CSS/JavaScriptを配置
- ビルド: 不要。サーバー処理・データベース・外部アップロードは行わない

## 2. プロダクト要件

### R-01 インポートとプライバシー

- `irealb://` と `irealbook://` の共有文字列を受け付ける。
- `.txt`、`.html`、`.htm` をファイル選択から受け付ける。
- インポートしたデータはブラウザ内で解析・表示し、運営者のサーバーへ送信しない。
- 曲データと表示設定はブラウザ内に保存し、再起動時に再利用できる。
- 入力が空、形式不正、サイズ超過、解析不能の場合は、画面上に利用者向けエラーを表示する。
- インポートデータを利用する権限があるかは利用者自身が確認する。

### R-02 Original 表示

- Original はインポート元の譜面構造を基準に表示する。
- リピート、番号付きエンディング、D.C.、D.S.、Fine、Segno、To Coda、Coda、複縦線、拍子、セクションを保持する。
- Original の表示を、Expanded の結果から逆算して生成してはならない。

### R-03 Expanded 表示

- Expanded は譜面上のリピートとジャンプを、上から下へ読む線形順に展開する。
- 通常リピートと番号付きエンディングを展開する。
- D.C. は先頭、D.S. は直前の Segno へ戻る。
- `al Fine` は対象範囲の Fine まで、`al Coda` は To Coda から Coda へ進む。
- 展開後はリピート点とエンディング括弧を除く。ただし、元のセクション境界・複縦線は保持する。
- ジャンプ経路が不完全な場合は無限ループにせず、警告を出して安全な線形表示に戻す。
- 特殊な文章指示や壊れたリピート情報を含む場合は、Original を正とする。

### R-04 To Coda 単独の扱い

- D.C./D.S. が存在しない `To Coda`/`Coda` の組は、Expanded でジャンプさせない。
- この場合は、書かれた小節をすべて残す。
- ただし、その Coda セクション内に通常リピートがあれば、そのリピートだけは通常どおり展開する。

### R-05 U と End

- iReal の `U` トークンは一律に End 小節として解釈する。
- Original、Expanded ともに End を小節内の右側へ寄せて表示する。
- End 小節が通常リピートの中にある場合、Expanded では最終コーラスの出現だけに End を表示する。
- 同じソース小節から生成された複数の出現を、End の重複表示として残してはならない。

### R-06 Fine / End の表示規則

次の規則は、Expanded での視覚表示に適用する。

1. D.S./D.C. がなく、Fine だけが通常リピート内にある場合、Fine は最終コーラスだけに残す。
2. D.S./D.C. がなく、End だけが通常リピート内にある場合、End は最終コーラスだけに残す。
3. Fine と End が同じ小節にある場合、通常リピートでは Fine を表示し、End は表示しない。
4. D.S./D.C. の経路が機能的に消費する Fine は、Expanded で表示しない。
5. その機能的な停止が Fine と End の同一小節で表されている場合、End も表示しない。
6. D.S./D.C. によって消費されない Fine / End は、最終到達箇所に限って表示する。
7. `Fine` が見えている小節では、レンダラーが End を追加表示してはならない。

「表示を消す」ことと「経路の停止条件を消す」ことを混同しない。停止条件は展開処理で消費し、表示記号だけをレンダリング段階で制御する。

### R-07 番号付きエンディング

- 1番、2番、3番以降のエンディングを、それぞれ指定された回数だけ通る。
- D.C./D.S. から `al 3rd End.` などへ戻る場合、対象エンディングを二重出力しない。
- エンディングの範囲は、iReal が番号を最初の小節にしか付けていない場合も、リピート終端まで正しく推定する。

### R-08 音楽表記と移調

- ルート、クオリティ、ベース音、代替コード、拍子、セクションを保持する。
- `add2`、`add4`、`add6`、`add9`、`add11` などの add 系拡張は、別の拡張へ置き換えず、書かれた数字を保持する（`add9` を `add2` に変換しない）。
- `m`、`min`、`-` のマイナー指定は、Settings の Minor 表記（`m` / `−` / `min`）へ変換する。add 系拡張の数字はこの変換で変更しない。
- Major 7、minor、half diminished、diminished 7 の設定を反映する。
- Auto / flat / sharp の綴り設定と移調を組み合わせても、コードの音名を壊さない。
- 移調量がゼロで Auto の場合、元譜の理論的な綴り（例: Cb、Fb、E#、B#）を保持する。

### R-09 狭い画面のUI

- 画面幅が狭い場合、上部コントロール列は横スクロールできる。
- スクロールバーは表示せず、左右端のフェードで「横にスクロール可能」であることを示す。
- コントロールを無理に極小化して押し込まない。
- 検索欄にフォーカスしてもブラウザのページ全体が不自然にズームせず、譜面領域を必要以上に狭めない。
- スマートフォンでは Fullscreen ボタンを表示しない。
- `?` と歯車は、♭/# と同程度以上のタップ領域を持ち、アイコンをボタン中央に配置する。
- キー表示（例: `B♭`）はボタン内で上下中央に揃える。

### R-10 公開表示・ライセンス

- Help または README に、ローカル処理・利用者の権利確認・iReal Pro の商標非提携を明記する。
- iReal Pro は Technimo LLC の商標であり、本アプリは同社と提携・承認関係にない旨を維持する。
- 変更をコミットするときは GitHub 上の表示名を `over-keys`、ローカル作者名を `over_keys` とする。

## 3. 非目標（仕様として実装しないもの）

- D.C./D.S. がない To Coda/Coda を、演奏解釈として自動ジャンプさせない。
- アプリからの音声再生や演奏シミュレーションを行わない。
- 特殊な自由記述を推測して、Original の内容を勝手に書き換えない。
- インポートされた譜面をサーバーへアップロードしない。
- スマートフォンで Fullscreen を必須機能にしない。

## 4. Validation の実施方法

### 4.1 変更前後の基本チェック

```sh
git diff --check
git status --short
```

HTML を直接開く場合と、ローカルHTTPサーバーで開く場合の両方で確認する。ブラウザの開発者コンソールにエラーがないことを確認する。

```sh
python3 -m http.server 4174 --bind 127.0.0.1
```

### 4.2 iReal 解析の回帰検証

検証用の譜面データは、利用権限のあるローカルファイルを使う。現在の基準ファイルは `jazz1460.txt` で、リポジトリには含めない。

| 項目 | 現行基準値 |
| --- | ---: |
| 収録曲数 | 1460 |
| 元データの `U` 件数 | 157 |
| パーサーが作る End 件数 | 157 |
| Expanded の End データ件数 | 154 |
| 3番エンディングの重複出力 | 0件 |
| 警告がある曲 | 5曲（既知の警告のみ） |

基準ファイルの識別用 SHA-256（2026-08-06時点）:

```text
d5b6747f592a26ca959610977fdce07589229d00f8b6b92c0b1197dd8dce5598
```

解析変更では、曲数が1460であること、`U` と End の件数が一致すること、重複出力が0であることを必須にする。Expanded の End 件数は、機能的に消費された Fine+End を非表示にする仕様を含む基準値である。

### 4.3 最小の音楽構造ケース

次の曲を毎回確認する。曲名は iReal データ内の表記に合わせる。

| 曲 | 目的 | Expandedで期待する表示 |
| --- | --- | --- |
| Cold Duck Time | D.C./D.S.なし、通常リピート内の Fine+End | 最終コーラスに Fine のみ |
| Dear John | D.C./D.S.なし、通常リピート内の End | 最終コーラスに End のみ |
| First Song | D.C./D.S.なし、通常リピート内の End | 最終コーラスに End のみ |
| Intrepid Fox, The | D.S./D.C.で機能的に消費される Fine+End | Fine/End とも非表示 |
| Like A Lover | D.S./D.C.で機能的に消費される Fine+End | Fine/End とも非表示 |
| And The Angels Sing | 3番エンディングへのジャンプ | 3番エンディングを二重出力しない |
| Most Beautiful Girl In The World, The | D.S. al 3rd End. と Segno 周辺 | 対象エンディングへ1回だけ到達 |
| Del Sasser | D.S. al Fine と通常リピート | Fineを機能的停止として処理し、不要な表示を残さない |

### 4.4 合成チャートの必須ケース

実データだけでなく、最小の合成バー列でも確認する。合成データは著作権に依存しない。

1. `C7|UD7|E7Z` を解析し、2小節目だけが `endMarker: true` になる。
2. そのバー列を Expanded にし、End が最終到達出現だけに残る。
3. Fine と End が同一バーにある通常リピートを作り、DOM上は Fine だけ見える。
4. D.C. al Fine または D.S. al Fine の経路を作り、Expanded のDOMに Fine/End が残らない。
5. 3番エンディングを指定するジャンプを作り、対象ソース小節の出現回数が1になる。
6. D.C./D.S.なしの To Coda/Coda を作り、Coda へジャンプせず、書かれた小節をすべて保持する。

### 4.5 ブラウザ表示の必須ケース

| 画面幅 | 確認内容 |
| ---: | --- |
| 1280px前後 | Original/Expanded、設定、ヘルプ、移調、譜面の4小節組みを確認 |
| 390px前後 | 検索フォーカス時にページ全体が拡大しない。入力後も譜面幅が戻る |
| 390px前後 | 上部コントロールを左右にスワイプでき、スクロールバーは見えず、端のフェードが出る |
| 390px前後 | `?`、歯車、♭、♯のタップ領域とアイコン位置を確認。Fullscreenは非表示 |
| 350px以下 | ツールバーが譜面を隠さず、検索欄・コントロール列が操作可能 |

ブラウザ検証では、次も確認する。

- コンソールエラーが0件。
- `Original` と `Expanded` の切替後に検索結果と選択曲が壊れない。
- リロード後もインポート曲・選択曲・表示設定が復元される。
- Help、English help、ライセンス、第三者通知へのリンクが開く。

## 6. 既知の注意点

- iReal の共有データは、同じ見た目でも記号の置かれた小節やジャンプ指示が異なることがある。スクリーンショットやOriginal表示を基準に判断する。
- `jazz1460.txt` に含まれる不完全リピートや旧式コードトークンの警告は、警告が出ること自体を失敗としない。ただし、警告内容が変わる場合は理由を記録する。
- Fine/End を非表示にする修正では、「経路を正しく止めた結果として非表示」なのか、「表示だけを隠した」のかを必ず分けて確認する。
- 外部フォントが読み込めない場合でも、Unicodeフォールバックで譜面を読める状態を維持する。
